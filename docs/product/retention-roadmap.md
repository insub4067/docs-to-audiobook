# 개인 오디오북 정착 로드맵

> 상태: 진행 중  
> 갱신일: 2026-08-01  
> 대상: 제품·디자인·개발 에이전트

## 제품 방향

Docs to Audiobook의 다음 목표는 기능 수를 늘리는 것이 아니라, 개인 학습·독서 사용자가 문서를 오디오북으로 만들고 여러 기기에서 계속 듣도록 만드는 것이다.

- 핵심 사용자: 모바일에서 개인 문서를 반복 청취하는 개인 학습·독서 사용자
- 우선 목표: 생성 이후의 재생·재방문 정착
- 수익화: 정착 지표가 확보된 뒤 검증한다.
- 제외: 팀 협업, 교육기관 관리, 프론트엔드 프레임워크 전환, 결제 구현

## 성공 지표

다음 지표를 기준으로 기능 우선순위를 정한다.

| 지표 | 정의 | 목적 |
| --- | --- | --- |
| 생성 성공률 | 생성 시작 대비 오디오 수신 완료 비율 | 핵심 가치 전달의 신뢰성 확인 |
| 첫 재생률 | 생성 완료 후 첫 재생을 시작한 비율 | 생성과 청취 사이의 이탈 확인 |
| 첫 재생까지의 시간 | 생성 완료부터 첫 재생까지 걸린 시간 | 활성화 흐름 개선 |
| 7일 재청취율 | 첫 재생 후 7일 안에 다시 재생한 사용자 비율 | 제품 정착 측정 |

## 우선순위

### Now — 신뢰성·연속성

1. 생성 작업의 상태와 결과를 영속화해 재배포·인스턴스 재시작에도 유실되지 않게 한다.
2. 로그인 계정의 오디오북 재생 위치·속도·반복 모드를 기기 간 동기화한다.
3. 라이브러리에서 제목을 수정하고, 마지막 재생 위치에서 바로 이어 듣게 한다.
4. 생성·재생·실패 이벤트를 수집해 위 성공 지표의 기준선을 만든다.

### Next — 활성화·공유 검증

1. 기본 제공 도서와 업로드 흐름을 개선해 첫 재생까지의 단계를 줄인다.
2. 공유 링크 열람, 내 라이브러리 저장, 재생 완료를 측정한다.
3. 공유 링크를 24시간 임시 저장으로 유지할지 영속 공유로 전환할지 데이터로 결정한다.

### Later — 검증 후 투자

1. 무료 한도와 유료 가치 제안을 소규모로 검증한다.
2. 개인 사용자 정착이 확인된 뒤 팀·교육기관 기능을 검토한다.
3. Vanilla JS가 기능 개발 속도를 실제로 저해할 때만 프레임워크 전환을 검토한다.

## 현재 구현 상태

### 완료

- 문서 변환, 음성 생성, IndexedDB 로컬 라이브러리, Google 로그인, Supabase 오디오 저장·동기화, 공유 링크가 구현되어 있다.
- `codex/retention-foundation` 브랜치에서 재생 상태 API와 제목 수정 API·UI를 추가 중이다.
  - 재생 상태는 `playback_history` 테이블에 최신 시각 기준으로 저장한다.
  - 리더는 5초마다 로컬 위치를 저장하고, 30초마다·리더 종료 시 클라우드에 동기화한다.
  - 제목 수정은 로컬과 클라우드 메타데이터를 함께 수정한다.
- `/admin` 관리자 대시보드는 허용된 이메일만 접근할 수 있으며, 사용자 수·활성 사용자·생성 성공률·재생 시작·1주 재방문율을 개인 콘텐츠 없이 집계한다.

### 미완료

- 생성 작업 영속화 및 재시작 복구
- 작가 메타데이터 편집
- 홈의 ‘이어서 듣기’ 전용 진입점
- 공유 링크 보관 정책 검증

## 결정이 필요한 항목

생성 작업 영속화는 원문 보관 정책을 먼저 정해야 한다.

| 선택지 | 장점 | 비용·위험 |
| --- | --- | --- |
| Supabase에 작업·원문 저장 | 재시작 후 이어서 처리 가능, 작업 상태를 복구 가능 | 개인정보 문서의 저장 기간·삭제 정책·접근 통제가 필요 |
| 생성 중에만 메모리 보관 | 원문 보관을 최소화 | 재배포·장애 시 진행 중인 작업은 실패 처리 |

이 결정 전에는 임시 파일·프로세스 메모리 기반 생성 구조를 대규모로 변경하지 않는다.

## 구현 원칙

- 새 기능은 성공 지표 중 하나를 직접 개선하거나 측정해야 한다.
- 클라우드 동기화는 로그인 사용자에게만 적용하고, 오프라인 중에는 IndexedDB를 우선한다.
- 서버 API는 사용자 소유권을 확인하며, 클라이언트는 네트워크 실패로 로컬 청취를 막지 않는다.
- 프론트엔드 변경 시 `static/sw.js`의 캐시 버전을 올린다.
- 코드 변경에는 동작을 검증하는 테스트를 함께 추가한다.

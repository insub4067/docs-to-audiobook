# TextAudio 소스코드 점검 보고서

작성일: 2026-08-09
대상 브랜치: `main`
대상 커밋: `8b03cad`

이 문서는 현재 소스코드와 로컬 테스트 결과를 기준으로, 다음 작업자가 바로 수정에
착수할 수 있도록 위험 요소와 권장 순서를 정리한 기록이다. 이번 점검에서는 소스를
수정하지 않았다. 운영 중인 Supabase 데이터와 Fly.io 로그는 확인 범위에 포함하지
않았다.

### 기준 커밋 변경 내용

`8b03cad`(`수정: ESLint 에러 4건 해소 — CI 실패 원인`)은 기능을 추가한 커밋이
아니라 정적 검사 실패를 고친 커밋이다.

- `frontend/Home/Home_View.vue`: 사용하지 않는 `useAuthStore` import와 변수 제거
- `frontend/Reader/Reader_Logic.vue`: 의도적으로 무시하는 localStorage 예외에
  설명을 추가해 `no-empty` 위반 해소
- `frontend/tests/now-playing-marker.test.ts`: 사용하지 않는 `nowPlayingId` import 제거
- `frontend/static/sw.js`: 프론트 변경에 맞춰 캐시 버전을 `2026.08.09.18`로 갱신

이 보고서의 ESLint 통과 결과와 프론트 코드 평가는 위 변경이 반영된 상태를 기준으로
한다. 커밋은 `main`과 `origin/main`에 모두 반영돼 있었다.

## 1. 결론

현재 코드는 서비스 가능한 상태이며 테스트 기반도 안정적이다. 프론트 테스트 203개,
백엔드 테스트 324개가 통과했고 백엔드 커버리지는 87%다. 관리자 SPA와 메인 SPA의
프로덕션 빌드도 성공했다.

새 기능을 더 붙이기 전에는 다음 일곱 가지를 먼저 처리하는 편이 안전하다.

1. 테스트 성공 후에만 배포되도록 CI/CD 순서 수정
2. `.dockerignore` 추가
3. URL 가져오기 DNS 재바인딩 방어
4. 뉴스·라이브러리 TTS의 동시성 및 메모리 제한
5. 폴더 순환 구조 방지
6. 구글 로그인 이메일 검증 강화
7. Storage 업로드와 DB 저장 사이의 실패 보상

### 로컬 검증 환경의 미비점

- 운영은 Python 3.11이지만 현재 로컬 가상환경은 Python 3.14다.
- `youtube-transcript-api`가 로컬 가상환경에 없어 YouTube 테스트 파일을 수집하지
  못했다. 패키지는 `backend/requirements.txt`에는 선언돼 있다.
- `ruff`가 로컬 가상환경에 없어 실행하지 못했다. 패키지는
  `backend/requirements-dev.txt`에는 선언돼 있다.
- 프론트 빌드와 테스트는 통과했지만 Vite의 CJS API 및 `package.json` 모듈 타입
  관련 경고가 남아 있다.

권장 조치: Python 3.11로 가상환경을 다시 만들고 운영·CI와 같은 requirements를
설치한 뒤 전체 검증을 한 번 더 실행한다.

## 3. 즉시 수정 권고

### P0-1. 테스트 실패와 관계없이 운영 배포가 진행됨

**근거**

- `.github/workflows/ci-cd.yaml:51-60`
- `deploy` 작업에 `needs: test`가 없고 테스트와 병렬로 실행된다.

**영향**

테스트·빌드·린트가 실패한 커밋도 Fly.io에 먼저 배포될 수 있다. 현재 테스트 수가
많아도 배포 차단 조건으로 연결되지 않으면 회귀 방지 장치가 운영을 보호하지 못한다.

**권장 변경**

- `deploy`에 `needs: test`를 추가한다.
- `main`의 `push`에서만 배포한다는 기존 조건은 유지한다.

**완료 조건**

- 실패하는 임시 테스트가 있는 워크플로에서 `deploy`가 `skipped` 처리된다.
- 모든 검사가 성공한 경우에만 배포가 시작된다.

### P0-2. Docker 이미지에 로컬 비밀 파일과 개발 환경이 포함될 수 있음

**근거**

- 저장소 루트에 `.dockerignore`가 없다.
- `Dockerfile:35`가 `COPY --chown=user:user . $HOME/app`으로 전체 컨텍스트를
  복사한다.
- 로컬에는 Git에서 무시되는 `backend/.env`, `.venv`, `frontend/node_modules`가
  존재한다.
- 현재 로컬 빌드 컨텍스트 후보의 전체 크기는 약 444MB다.

**영향**

GitHub Actions 체크아웃에는 로컬 `.env`가 없지만, 개발자 컴퓨터에서
`flyctl deploy`를 실행하면 비밀 값과 불필요한 개발 파일이 원격 빌드 컨텍스트와
최종 이미지에 포함될 수 있다. 이미지 크기와 업로드 시간도 불필요하게 증가한다.

**권장 변경**

`.dockerignore`에 최소한 다음 항목을 추가한다.

```text
.git
.env
**/.env
.venv
**/__pycache__
**/.pytest_cache
**/.ruff_cache
frontend/node_modules
frontend/static/dist
backend/uploads
```

**완료 조건**

- Docker 빌드 컨텍스트에 `.env`, `.venv`, `node_modules`가 포함되지 않는다.
- 컨테이너 안에 `backend/.env`가 존재하지 않는다.
- 두 SPA 빌드 결과와 FastAPI 실행에는 영향이 없다.

## 4. 높은 우선순위

### P1-1. URL 가져오기에서 DNS 재바인딩으로 SSRF 방어 우회 가능

**근거**

- `backend/routes/extract_url.py:27-44`에서 호스트의 IP를 검사한다.
- `backend/routes/extract_url.py:61-67`의 실제 `requests.get()`은 호스트를 다시
  조회한다.

**영향**

첫 DNS 조회에는 공인 IP를 반환하고 실제 연결 시 내부 IP를 반환하는 방식으로
사설망·메타데이터 주소 차단을 우회할 여지가 있다. 로그인과 요청 제한이 공격 범위를
줄이지만 네트워크 경계 검증 자체는 완전하지 않다.

**권장 변경**

- 검증한 IP에 연결을 고정한다.
- HTTP `Host`와 HTTPS SNI는 원래 호스트를 유지한다.
- 현재처럼 리다이렉트의 각 단계도 다시 검증한다.
- DNS 재바인딩을 재현하는 테스트를 추가한다.

### P1-2. 관리자 콘텐츠 TTS가 청크 수만큼 동시 요청을 생성함

**근거**

- `backend/routes/tts.py:156-218`의 `synthesize_document()`는 모든 청크를
  `asyncio.gather()`로 한 번에 실행하고 결과 오디오 전체를 메모리에 보관한다.
- 뉴스, 라이브러리, 기본 오디오북이 이 함수를 사용한다.
- 일반 대용량 작업은 `backend/routes/tts.py:225-340`의
  `synthesize_document_to_file()`에서 최대 5개 흐름으로 제한하고 디스크에 쓴다.
- Fly.io 머신은 공유 CPU 1개와 메모리 1GB다.

**영향**

긴 작품 하나가 수백·수천 개의 TTS 요청과 큰 오디오 버퍼를 동시에 만들 수 있다.
관리자가 여러 작품을 등록하면 TTS 공급자 제한, 메모리 부족, 다른 사용자 요청 지연으로
이어질 수 있다.

**권장 변경**

- 뉴스·라이브러리·기본 오디오북도 디스크 기반 제한 동시성 경로를 재사용한다.
- 관리자 JSON의 항목 수와 작품별 본문 길이에 명시적인 상한을 둔다.
- 긴 입력에서 실제 동시 합성 수가 설정값을 넘지 않는 테스트를 추가한다.

### P1-3. 폴더 순환 구조 생성 가능

**근거**

- `backend/routes/folders.py:94-103`은 자기 자신으로 이동하는 경우만 막는다.
- 현재 테스트에는 조상 폴더를 자손 아래로 옮기는 시나리오가 없다.

**재현 예시**

```text
A
└─ B
   └─ C
```

이 상태에서 A의 상위 폴더를 C로 지정하면 `A → B → C → A` 순환이 만들어진다.

**권장 변경**

- 이동 대상이 현재 폴더의 자손인지 서버에서 확인한다.
- 자기 자신과 자손으로의 이동을 모두 400으로 거부한다.
- 깊이가 여러 단계인 회귀 테스트를 추가한다.

### P1-4. 구글 로그인에서 검증된 이메일인지 확인하지 않음

**근거**

- `backend/routes/auth_social.py:66-85`는 ID 토큰을 검증하지만
  `email_verified`를 확인하지 않는다.
- `backend/routes/auth_social.py:95-128`은 이메일로 기존 사용자를 찾고 연결한다.

**영향**

이메일이 계정 연결 키이므로 검증되지 않은 이메일을 받아들이면 잘못된 계정 연결로
이어질 수 있다.

**권장 변경**

- `email_verified is True`인 토큰만 허용한다.
- 이메일과 `sub`가 없는 토큰도 명시적으로 거부한다.
- 미검증 이메일과 정상 토큰을 각각 검사하는 테스트를 추가한다.

### P1-5. 서비스 워커 설치가 외부 자원 하나의 실패로 중단될 수 있음

**근거**

- `frontend/static/sw.js:6-20`은 로컬 자원, unpkg, Google Fonts를 하나의
  `cache.addAll()` 호출로 묶는다.
- `cache.addAll()` 항목 중 하나라도 실패하면 설치 작업 전체가 실패한다.

**영향**

외부 CDN이나 글꼴 서버의 일시 장애가 PWA 업데이트, 오프라인 캐시, 웹 푸시 등록까지
막을 수 있다.

**권장 변경**

- 설치에 반드시 필요한 같은 출처 자원만 `cache.addAll()`로 캐시한다.
- 외부 자원은 설치 성공 조건에서 제외하거나 개별 실패를 허용한다.
- 필수 자원 404 시 설치 실패, 선택 자원 실패 시 설치 성공을 검증한다.

## 5. 중간 우선순위

### P2-1. Storage 업로드 후 DB 저장 실패 시 고아 파일 발생

**해당 경로**

- `backend/routes/library.py:82-118`
- `backend/routes/news.py:101-130`
- `backend/routes/tts.py:419-460`

문장 JSON 업로드 실패 시 MP3를 지우는 처리는 있지만, 두 파일 업로드가 성공한 뒤
`audiobooks` insert가 실패하면 둘 다 Storage에 남는다.

**권장 변경**

DB insert 실패 시 방금 올린 MP3와 문장 JSON을 모두 삭제하는 보상 처리를 공통
함수로 묶는다. 삭제 실패는 원래 오류를 덮지 말고 별도로 기록한다.

### P2-2. 클라이언트 업로드 중단 시 빈 DB 행 발생

`backend/routes/audiobooks.py:46-85`는 DB 행을 먼저 만든 뒤 서명된 업로드 URL을
반환한다. 사용자가 업로드를 시작하지 않거나 중간에 앱을 닫으면 파일이 없는 행이
남는다.

단기적으로는 `pending` 상태와 만료 정리를 추가하고, 장기적으로는 업로드 완료
확인 뒤 행을 활성화하는 흐름을 권장한다.

### P2-3. service role 누락 시 anon 키로 조용히 대체

`backend/auth.py:55-82`는 `SUPABASE_SERVICE_ROLE_KEY`가 없으면 경고만 출력하고 anon
키를 사용한다. 관리자 및 서버 내부 작업은 권한 오류로 뒤늦게 실패하게 된다.

service role이 필요한 경로는 시작 시점 또는 클라이언트 생성 시점에 명확한 설정 오류로
실패시키는 편이 진단하기 쉽다.

### P2-4. 내부 예외 문자열을 HTTP 응답에 노출

백엔드 28곳에서 `detail=f"... {e}"` 형태로 내부 예외를 사용자에게 반환한다.
DB 테이블명, Storage 응답, 내부 구현 정보가 노출될 수 있다.

- 사용자 응답: 고정된 한국어 오류 메시지
- 서버 로그: 예외 스택과 요청 식별자
- 사용자 문의용: 요청 식별자만 노출

위 구조로 분리한다. `backend/routes/system.py:296`의 클라이언트 오류 메시지도 줄바꿈을
제거하거나 구조화 로그로 남겨 로그 위조 가능성을 줄인다.

### P2-5. 1년 유효 JWT를 localStorage에 저장

- `backend/auth.py:13-14`: 기본 유효기간 525,600분
- `frontend/Auth/Auth_Logic.vue:131-173`: 토큰을 localStorage에 저장

현재 구조에는 서버 측 토큰 폐기 장치가 보이지 않는다. 토큰이 유출되면 로그아웃해도
만료까지 사용할 수 있다. PWA 로그인 유지 경험을 해치지 않으면서 보안을 높이려면 짧은
액세스 토큰과 회전 가능한 갱신 토큰 구조가 필요하다.

### P2-6. 단일 머신과 프로세스 메모리에 묶인 상태

- `backend/state.py:91`: 요청 제한 버킷
- `backend/state.py:212-220`: 업로드 텍스트, 작업, OCR 진행 상태
- `fly.toml:19-27`: 메모리 상태 때문에 단일 머신 강제

현재 사용자 규모에서는 운영할 수 있지만 머신 장애와 배포 시 작업 유실 가능성이 있고
수평 확장이 불가능하다. 사용자가 늘기 전에 작업 상태를 DB나 Redis로 옮기는 별도 설계가
필요하다.

## 6. 낮은 우선순위와 유지보수 항목

### 앱 아이콘 크기

`frontend/static/textaudio-icon.png`는 1254×1254, 약 2.5MB다. 서비스 워커가 이를
미리 캐시하고 알림·홈 화면 아이콘에도 사용한다. 192px와 512px 파일을 따로 만들고
압축하면 설치와 첫 로딩 비용을 크게 줄일 수 있다.

### CORS 메서드 누락

`backend/main.py:18-30`은 GET·POST만 허용하지만 API에는 PATCH·DELETE가 있다.
운영 프론트는 같은 출처라 영향이 적지만, 별도 출처로 프론트를 띄우는 로컬 개발에서는
프리플라이트가 실패할 수 있다.

### 폐기 예정 API 경고

테스트에서 다음 경고가 반복된다.

- FastAPI `@app.on_event()` → lifespan 사용 권장
- Pydantic 클래스형 `Config` → `ConfigDict` 사용 권장
- `datetime.utcnow()` → 시간대가 있는 UTC 시각 사용 권장
- Supabase 클라이언트의 `timeout`, `verify` 인자 변경 예정

당장 장애를 만들지는 않지만 주요 의존성 업그레이드 전에 정리해야 한다.

### 개발 도구 경고

`frontend/package.json`에 모듈 타입이 없어 ESLint가 설정 파일을 ES module로 다시
해석한다. Vite의 CJS Node API 경고도 함께 발생한다. 기능에는 영향이 없으므로 다른
우선 작업을 마친 뒤 설정을 정리한다.

## 8. 변경 시 공통 완료 기준

각 작업은 다음 조건을 충족해야 완료로 본다.

1. 문제를 재현하거나 위험 조건을 고정하는 테스트가 먼저 존재한다.
2. 관련 테스트와 기존 전체 테스트가 통과한다.
3. 관리자 SPA와 메인 SPA 빌드가 모두 성공한다.
4. 백엔드 Ruff와 프론트 ESLint가 통과한다.
5. 프론트 소스를 수정했다면 `frontend/static/sw.js`의 캐시 버전을 올린다.
6. 변경 범위와 직접 관계없는 리팩터링은 포함하지 않는다.

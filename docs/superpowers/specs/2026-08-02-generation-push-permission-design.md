# 오디오북 생성 시 알림 권한 요청 설계

## 목표

로그인 사용자가 오디오북 생성 버튼을 누를 때 완료 알림이 아직 설정되지 않았다면, 해당 사용자 제스처 안에서 iOS 알림 권한과 Push 구독을 한 번 요청한다. 알림 설정 결과는 오디오북 생성 성공 여부에 영향을 주지 않는다.

## 선택한 방식

`static/js/notifications.js`가 Push 설정, 서비스워커 등록, 브라우저 구독, 서버 저장을 계속 전담한다. 초기화가 끝나면 `window.__requestPushNotificationSubscription()`을 제공하고, `static/app.js`의 생성 버튼 처리기가 합성을 시작하기 전에 이 함수를 호출한다.

초기화 과정에서 `/api/push/config`와 서비스워커 등록을 미리 준비한다. 생성 버튼을 눌렀을 때 네트워크 설정 조회부터 시작하면 iOS의 사용자 활성 상태가 사라질 수 있으므로, 권한 요청 함수는 이미 준비된 설정만 사용한다. 준비되지 않았으면 알림 설정을 건너뛰고 생성은 계속한다.

## 상태별 동작

- 이미 현재 사용자의 서버 구독이 연결됨: 아무 작업도 하지 않는다.
- 권한이 `denied`: 다시 요청하지 않고 생성만 진행한다.
- 권한이 `default`: 생성 버튼의 사용자 제스처에서 권한을 요청한다.
- 권한이 `granted`지만 구독이 없음: Push 구독을 생성하고 서버에 저장한다.
- 구독 또는 서버 저장 실패: 생성은 계속하고 기존 알림 설정 실패 토스트를 표시한다.

프로필 메뉴의 수동 알림 토글도 동일한 구독 함수를 사용해 동작 차이를 만들지 않는다. 수동 토글의 구독 해제 동작은 유지한다.

## 사용자 경험

권한 요청은 앱 최초 실행이 아니라 알림의 필요성이 생기는 생성 시점에만 표시한다. 사용자가 거절해도 오디오북 생성은 중단되지 않는다. 허용되면 프로필 메뉴 문구를 `완료 알림 켜짐`으로 즉시 갱신한다.

## 검증

- 생성 탭에서 미구독 상태일 때 권한 요청과 서버 등록이 한 번 실행되는 테스트
- 이미 구독됨·권한 차단 상태에서는 다시 요청하지 않는 테스트
- 알림 설정 실패 뒤에도 합성 함수가 호출되는 테스트
- 기존 수동 토글의 켜기·끄기 테스트 유지
- 전체 테스트 통과와 서비스워커 캐시 버전 증가

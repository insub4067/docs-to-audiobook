# 비로그인 1회 오디오북 체험 설계

## 목표

로그인하지 않은 사용자가 이 브라우저에서 오디오북을 한 번 생성해 로컬에서 들을 수 있게 하고, 두 번째 생성부터는 로그인으로 유도한다. 체험 생성본은 로그인 직후 기존 클라우드 동기화로 업로드한다.

## 범위와 제약

- 체험 한도는 사람이나 계정이 아니라 브라우저·기기 기준 1회다. 브라우저 저장소를 지우면 다시 체험할 수 있다.
- 체험 생성본은 IndexedDB에만 저장한다. 비로그인 상태에서는 공유와 클라우드 저장을 제공하지 않는다.
- 파일 업로드와 텍스트 미리보기는 현재처럼 로그인 없이 허용한다. URL 본문 가져오기는 로그인 전용으로 유지한다.
- 이미 적용된 IP 기반 합성 요청 제한은 유지한다.
- 로그인 사용자의 생성·작업 조회·다운로드 동작은 바꾸지 않는다.

## 설계

### 익명 생성 권한과 작업 접근

브라우저는 최초 체험 생성 전에 `localStorage`에 무작위 익명 세션 식별자를 만든다. 합성 요청, 진행 조회, 오디오 다운로드에 `X-Anonymous-Session` 헤더로 이를 전송한다.

서버는 유효한 로그인 토큰이 있으면 기존 사용자 ID를 작업 소유자로 사용한다. 로그인 토큰이 없으면 익명 세션 식별자가 있을 때만 익명 작업을 만들고, 작업 소유자에 해당 식별자를 저장한다. 작업 상태와 오디오 엔드포인트는 로그인 사용자 ID 또는 같은 익명 세션 식별자만 통과시킨다. 따라서 다른 브라우저는 생성 작업의 진행률이나 오디오에 접근할 수 없다.

### 클라이언트 체험 한도

IndexedDB의 기본 제공본이 아닌 로컬 오디오북이 하나 이상이면 비로그인 상태에서 추가 생성을 막는다. 생성이 완료되면 체험본은 기존 로컬 항목과 같은 형식으로 저장된다. 생성 중인 작업도 한도에 포함하도록 별도 `anonymousTrialInProgress` 값을 유지해 중복 요청을 막고, 성공·실패 시 해제한다.

두 번째 생성을 막을 때는 기존 로그인 유도 바텀시트를 재사용하고, 제목과 설명을 “추가 생성은 로그인 후 가능해요”, “로그인하면 현재 설정 그대로 이어서 만들고, 기기에 저장된 체험본도 클라우드에 보관해요”로 바꾼다.

### 로그인 뒤 동기화

로그인 성공 후 앱 UI를 표시하는 시점에 기존 `syncWithCloud()`를 호출한다. 이 함수는 `cloudId`가 없는, 기본 제공본이 아닌 로컬 오디오북을 클라우드에 업로드하므로 체험본을 별도 이전 로직 없이 업로드할 수 있다. 업로드가 실패하면 로컬 체험본은 보존되고 다음 앱 시작 또는 새로고침 때 재시도한다.

## 오류 처리

- 익명 세션 헤더가 없거나 비어 있으면 익명 합성·작업 조회·다운로드는 401을 반환한다.
- 다른 익명 세션 또는 다른 로그인 사용자가 작업에 접근하면 403을 반환한다.
- 합성 실패 시 진행 표시와 `anonymousTrialInProgress`를 제거해 사용자가 체험을 다시 시도할 수 있게 한다.
- 로그인 직후 동기화 실패는 로그인 자체를 실패시키지 않고 콘솔에 기록한다. 로컬 데이터는 삭제하지 않는다.

## 검증 기준

1. 비로그인 요청은 익명 세션 헤더가 있을 때만 합성 작업을 생성할 수 있다.
2. 생성한 익명 세션만 해당 작업의 상태와 오디오를 조회할 수 있다.
3. 로그인 사용자는 기존 인증 흐름으로 합성할 수 있다.
4. 비로그인 사용자는 로컬 생성본이 있으면 두 번째 생성 요청 대신 로그인 유도 화면을 본다.
5. 로그인 성공 시 `cloudId`가 없는 체험본이 기존 동기화 경로를 통해 업로드된다.
6. 기존 전체 테스트와 프론트엔드 가이드 테스트가 통과한다.

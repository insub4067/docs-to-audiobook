# 백그라운드 작업 로딩 행 유지 설계

## 목표

서버 백그라운드 오디오북 생성 요청을 보관함 최상단에 `생성 중` 행으로 즉시 표시하고, 새로고침이나 앱 재실행 뒤에도 미완료 작업을 한 번만 복원한다. 작업 완료 뒤에는 클라우드에서 받은 실제 오디오북 행으로 교체하며 실패한 작업은 제거한다.

## 선택한 방식

기존에 사용자별로 `localStorage`에 저장하는 대기 작업 ID와 `/api/background-jobs/{job_id}` 상태 조회를 그대로 사용한다. 별도의 활성 작업 목록 API나 테이블 변경은 추가하지 않는다.

작업 ID를 DOM의 `data-background-job-id`에 기록해 동일한 작업의 로딩 행을 중복 생성하지 않는다. `rememberBackgroundJob` 직후 현재 화면에 행을 유지하고, 알림 모듈 초기화 때 저장된 대기 작업마다 행 복원을 요청한다.

## 상태 흐름

1. 합성 API가 `background_started: true`를 반환하면 작업 ID를 저장하고 기존 진행 행에 작업 ID를 연결한다.
2. 새로고침 후 알림 모듈이 저장된 작업 ID를 읽어 보관함 최상단에 로딩 행을 복원한다.
3. 상태가 `queued` 또는 `processing`이면 행을 유지한다.
4. 상태가 `completed`이면 클라우드 동기화가 성공한 뒤 대기 작업 키와 로딩 행을 제거하고 목록을 실제 데이터로 다시 그린다.
5. 상태가 `error`이면 대기 작업 키와 로딩 행을 제거하고 오류 토스트를 표시한다.

## 구독과의 관계

Push 구독은 이번 변경의 선행 조건이 아니다. 구독이 없어도 앱이 열려 있으면 주기 조회와 포그라운드 복귀 확인으로 상태를 갱신한다. iOS 알림 권한은 사용자 동작이 필요하므로 홈 화면 설치만으로 자동 구독하지 않는다.

## 오류 및 중복 처리

- 상태 조회나 클라우드 동기화가 일시적으로 실패하면 로딩 행과 대기 작업 키를 유지해 다음 확인에서 재시도한다.
- 같은 작업 ID의 로딩 행이 이미 있으면 새 행을 만들지 않는다.
- 다른 사용자의 저장 키는 읽거나 표시하지 않는다.

## 검증

- 백그라운드 응답 직후 진행 행을 제거하지 않는 테스트
- 저장된 작업이 초기화 때 한 번만 복원되는 테스트
- 완료·실패 시 해당 작업의 행만 제거되는 테스트
- 기존 프런트엔드 및 전체 테스트 통과
- 프런트엔드 캐시 갱신을 위한 서비스워커 버전 증가

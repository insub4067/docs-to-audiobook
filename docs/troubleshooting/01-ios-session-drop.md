# iOS PWA에서 로그인이 저절로 풀림

## 증상

iOS PWA에서 앱을 다시 열면 오디오북 목록(로컬 데이터)은 그대로인데 로그인 버튼이
다시 활성화돼 있었다. 즉 세션이 저절로 끊긴 것처럼 보임. 재현이 간헐적이라 원인
추적이 어려웠다.

## 원인

`initializeAuth()`가 `fetchCurrentUser(token)` 호출이 실패하면 이유를 가리지 않고
무조건 `localStorage.removeItem("authToken")`로 토큰을 지웠다. 문제는 "실패"에
두 가지가 섞여 있었다는 것:

1. 토큰이 실제로 무효함 (401/403) — 이때는 지우는 게 맞다.
2. 네트워크 실패나 서버 5xx (예: Fly 배포 중 잠깐 응답이 안 될 때) — 토큰은
   멀쩡한데 일시적으로 통신이 안 됐을 뿐인데도 로그아웃 처리됐다.

그날 배포가 잦아서 재배포 중 앱을 열면 이 경로를 자주 탔다.

## 해결

`fetchCurrentUser`가 던지는 에러에 `authFailed` 플래그를 실어(401/403일 때만
`true`), `initializeAuth()`가 이 플래그를 볼 때만 토큰을 지우도록 바꿨다
(`static/app.js`). 네트워크 실패·5xx는 토큰을 그대로 두고 세션을 유지한다.

검증은 6가지 시나리오(네트워크 실패/503/500 → 세션 유지, 401/403 → 세션 해제,
200 → 세션 유지)를 fetch mock으로 직접 주입해 확인했다.

## 교훈

"요청이 실패했다"와 "인증이 실패했다"는 다른 사건이다. 실패를 뭉뚱그려 처리하면
꼭 이런 식으로 사용자가 원인을 알 수 없는 버그가 된다. HTTP 상태 코드 기준으로
분기를 명시적으로 나눠야 한다.

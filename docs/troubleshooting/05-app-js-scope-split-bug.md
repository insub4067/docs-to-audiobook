# 특정 순서로만 앱 초기화가 조용히 멈춤

## 증상

로그인 유도 UI 개선 작업 중, 파일을 업로드해도 미리보기 모달이 안 뜨고 아무
반응도 없어졌다. 콘솔 에러도 안 보였고, 재현이 로컬 캐시 상태에 따라 들쭉날쭉했다.

## 원인

`static/app.js`는 대부분의 코드가 `document.addEventListener("DOMContentLoaded", async () => { ... })`
클로저 안에 있었지만, 인증 관련 함수들(`showAppUI`, `initializeAuth`,
`isLoggedIn` 등)은 그 클로저가 끝난 뒤 파일 하단에 **전역 스코프**로 따로
떨어져 있었다. 이 경계는 코드를 훑어봐서는 안 보이고, 파일에서 닫는 괄호
`});`가 어디 있는지 직접 찾아야만 알 수 있었다.

새 기능(`updateGenerateHint()`, 클로저 안에 정의)을 전역 함수인 `showAppUI()`
안에서 호출하도록 짰는데, `showAppUI`는 클로저 밖이라 클로저 안의 함수를 볼 수
없다. `ReferenceError`가 발생했고, 이게 `await initializeAuth()` 호출 체인
안에서 났기 때문에 예외가 `DOMContentLoaded` 콜백 전체를 중단시켜, 그 아래
있던 모든 `addEventListener` 등록(파일 업로드 리스너 포함)이 실행조차 안 됐다.

## 해결

전역 스코프에 있던 인증/소셜로그인 관련 코드 블록 전체를 `DOMContentLoaded`
클로저 안으로 옮겨, 파일 전체가 하나의 스코프 규칙을 따르게 했다. 함수 선언은
호이스팅되므로 위치를 옮겨도 동작은 그대로였다 — 이동 전후 함수 인벤토리를
diff로 대조해 아무것도 안 사라졌는지 확인했다(죽은 코드였던 `showAuthUI()`
하나만 이 김에 제거).

## 교훈

스코프 경계가 코드를 눈으로 훑어서 안 보이면, 언젠가 그 경계를 넘나드는 실수가
나온다. "일부는 전역, 일부는 클로저"처럼 섞인 구조는 당장은 동작해도 유지보수
중 반드시 문제를 일으킨다. 실기기 브라우저 테스트로 "왜 아무 일도 안 일어나지"를
직접 재현해보지 않았다면 원인을 찾기 훨씬 어려웠을 것이다 — 콘솔에 에러가
찍히는지도 직접 확인해야 한다.

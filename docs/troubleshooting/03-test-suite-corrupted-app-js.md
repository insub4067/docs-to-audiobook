# 테스트를 돌렸더니 실서비스 파일이 깨짐

## 증상

테스트 스위트를 검토하려고 `pytest`를 실행했는데, `static/app.js`가 8줄짜리
문법 오류 파일로 바뀌어 있었다. 실서비스 프론트엔드가 통째로 망가진 상태.

## 원인

`tests/test_patch.py`라는 테스트가 있었는데, 이게 테스트라기보다 위험한 스크립트였다:

1. `open("static/app.js", "w").write(dummy_content)`로 실제 서비스 파일을
   더미 내용으로 덮어썼다.
2. 그 다음 `patch_app.py`(낡은 일회성 마이그레이션 스크립트)를 서브프로세스로
   실행해 이 더미 파일에 패치를 적용하려 시도했다.
3. `patch_app.py`의 "찾을 대상 문자열이 없으면 줄 단위로 폴백" 로직이, 더미
   내용에는 그 문자열이 당연히 없으니 폴백 경로를 탔고, 이 폴백이 백업 없이
   파일을 파괴적으로 덮어썼다.

결과적으로 어떤 백업도 복원 로직도 없이, pytest를 실행하는 것만으로 실제 서비스
파일이 파괴됐다.

## 해결

- `git checkout -- static/app.js`로 즉시 복구 (마지막 커밋 이후 변경분만
  미커밋 상태였어서 복구 가능했다).
- `tests/test_patch.py`와 `patch_app.py` 둘 다 완전히 삭제. 전자는 애초에
  존재해선 안 될 테스트였고, 후자는 이미 목적을 다한 일회성 스크립트였다.

## 교훈

- 테스트가 실서비스 파일 경로에 직접 쓰기 작업을 하면 안 된다. 필요하면
  `tmp_path` 픽스처로 격리된 임시 디렉터리를 쓴다.
- 목적을 다한 일회성 마이그레이션 스크립트는 남겨두지 말고 지운다 — 나중에
  실수로라도 다시 실행될 수 있는 채로 방치하면 이런 사고가 난다.
- `pytest`를 실행하기 전에는 항상 `git status`로 uncommitted 변경사항이 없는지
  확인하는 습관이 이런 사고의 피해를 줄인다(이번엔 다행히 커밋 안 된 변경만
  날아갔다).
